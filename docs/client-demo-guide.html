Fourty Distribution OS

A guided map of every page and feature for client demos: what it does, how the workflow flows, and exactly what each role can and cannot do.

Roles: Owner · Storekeeper · Subagent Stack: Next.js · Supabase · Web Push Currency default: ETB

User roles

Three roles share one app. Access is shaped by sidebar, soft-deny screens, and database rules (RLS).

Owner

Company control

Sees everything: all stores, catalog, team, audit, company policies, and review actions.

  • Create storekeepers & subagents
  • Review closeouts & remittances
  • Company-wide reports
Storekeeper

Store operations

Runs one store day-to-day: stock, sales, restock, closeout, adjustments, remittances.

  • Scoped to assigned store
  • Can review remittances
  • No Team / Audit / catalog admin
Subagent

Field sales

Sells from issued batches, remits cash, tracks own batches and notifications.

  • Batch-based sales only
  • Submit remittances
  • No inventory / closeout / reports

How access is enforced

flowchart LR A[User signs in] --> B{Authenticated?} B -->|No| L[Login] B -->|Yes| C[App shell] C --> D[Sidebar filtered by role] D --> E[Page UI] E --> F{Soft-deny?} F -->|Yes| G[Access denied panel] F -->|No| H[Full page features] H --> I[Supabase RLS] I --> J[Read / write allowed data only]
Middleware only checks login. Role limits come from the navigation menu, soft-deny pages, and database policies.

End-to-end business flows

Use these diagrams while narrating the product story from stock → sale → cash → review.

1. Store inventory loop

flowchart TD A[Owner creates Brands & Stores] --> B[Storekeeper / Owner Restocks inventory] B --> C[Stock available at store] C --> D[Record store sale + screenshot proof] D --> E[Inventory qty decreases] E --> F{Low stock?} F -->|Yes| G[Low-stock alert / restock again] F -->|No| H[Continue selling] H --> I[Daily closeout declares cash] I --> J[Owner reviews closeout]

2. Subagent batch loop

flowchart TD A[Owner / Storekeeper issues batch] --> B[Subagent receives cartons in hand] B --> C[Subagent records sale from batch] C --> D[Batch sold qty up · in-hand down] D --> E[Subagent submits remittance + optional proof] E --> F[Owner / Storekeeper confirms or rejects] F --> G[Return leftover stock optional] G --> H[Batch settled / closed]
